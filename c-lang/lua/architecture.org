** Overview

- User Interface
  - ~lua.c~: standalone interpreter — REPL and script execution
  - ~lua.h~: external C API
  - ~luac.c~: Lua compiler — saves bytecodes to files.

- Standard Libraries: ~lualib.h~
   - ~lauxlib.c~ and ~lauxlib.h~: auxiliary
   - ~lbaselib.c~: base — populates global environment
   - ~lcorolib.c~: coroutine
   - ~ldblib.c~: debug
   - ~liolib.c~: IO
   - ~lmathlib.c~: math
   - ~loadlib.c~: dynamic library loader
   - ~loslib.c~: operating system
   - ~lstrlib.c~: string
   - ~ltablib.c~: table
   - ~lutf8lib.c~: UTF-8
   - ~linit.c~: library initializer

- Runtime State
  - ~lapi.c~ and ~lapi.h~: runtime interface, C API bridge
  - ~lstate.c~ and ~lstate.h~: local and global state management
  - ~lgc.c~ and ~lgc.h~: garbage collection
  - ~lmem.c~ and ~lmem.h~: memory management interface

- Foundation
  - ~luaconf.h~: general configuration
  - ~llimits.h~: basic types, limits, installation-dependent definitions
  - ~lctype.c~ and ~lctype.h~: character types
  - ~lfunc.c~ and ~lfunc.h~: auxiliary functions over prototypes and closures
  - ~lobject.c~ and ~lobject.h~: functions over Lua objects
  - ~lstring.c~ and ~lstring.h~: string table and string cache
  - ~ltable.c~ and ~ltable.h~: Lua table implementation
  - ~ltm.c~ and ~ltm.h~: tag methods

- Parsing and Compilation
  - ~lzio.c~ and ~lzio.h~: buffered IO streams
  - ~llex.c~ and ~llex.h~: lexical analyzer
  - ~lparser.c~ and ~lparser.h~: recursive descent with precedence climbing
  - ~lcode.c~ and ~lcode.h~: bytecode generation
  - ~ldump.c~ and ~ldump.h~: saves precompiled Lua chunks
  - ~lundump.c~ and ~lundump.h~: loads precompiled Lua chunks

- Execution
  - ~ldo.c~ and ~ldo.h~: function calls, error handling
  - ~lvm.c~ and ~lvm.h~: virtual machine — interpreter loop, bytecode dispatcher
  - ~lopcodes.c~ and ~lopcodes.h~: virtual machine opcodes
  - ~lopnames.h~: human-readable names for opcodes
  - ~ljumptab.h~: computed-goto table — alternative to switch-case dispatch

- Other
  - ~ldebug.c~ and ~ldebug.h~: debug interface
  - ~lprefix.h~: definitions that must come before any other header file

  === Runtime State ===

  A two-level state management design that separates shared global resources
  from per-thread execution state.


  +-----------------------+                    +----------------------+
  | lua_State (coroutine) |-----+        +---->| Base Type Metatables |
  +-----------------------+     |        |     +----------------------+
                                V        |
                            +--------------+   +-------------------+
  +------------------------>| Global State |-->| Bottom Value: nil |
  |                         +--------------+   +-------------------+
  |                             | | | | |                        +----------------+
  |                             | | | | +----------------------->| Error Handling |
  |         +-------------------+ | | +----------------------+   +----------------+
  |         |             +-------+ +-------+                |
  |         |             |                 |                |
  |         V             V                 V                V
  |   +----------+ +--------------+ +-----------------+ +-----------+
  |   | Registry | | String Table | | GC Object Lists | | Allocator |
  |   +----------+ +--------------+ +-----------------+ +-----------+
  |
  |             +-------------------------+
  +-------------| Lua State (main thread) |
                +-------------------------+
                           | | |
           +---------------+ | +-------------+
           |                 |               |
           V                 V               V
  +-----------------+ +--------------+ +------------+
  | Execution Stack | | Call Frames  | | Debug Hook |
  | +------------+  | | +----------+ | +------------+
  | | StackValue |  | | | CallInfo | |
  | +------------+  | | +----------+ |
  |       ...       | |     ...      |
  | +------------+  | | +----------+ |
  | | StackValue |  | | | CallInfo | |
  | +------------+  | | +----------+ |
  +-----------------+ +--------------+

  === Execution Stack ===

  A resizable array of StackValue objects. Serves as both the operand stack
  for the VM and storage for function arguments, local variables,
  and return values

  0                        1        2        3     n             m
  +------------------------+--------+--------+-----+-------------+
  | Slot 0 (base function) | Slot 1 | Slot 2 | ... | EXTRA_STACK |
  +------------------------+--------+--------+-----+-------------+

  === Call Frames ===

  CallInfo represents a single call frame. Each active function has one
  CallInfo node in the call chain. A series of call frames forms
  a doubly-linked list.

  +---------------+
  | base_ci       |
  |---------------|--------------------------------------------------------------+
  | Embedded      |                                                              |
  +---------------+                                                              V
  +---------------+   +------------+             +------------+             +----------+
  | ci            |   | CallInfo   |- previous ->| CallInfo   |- previous ->| CallInfo |
  |---------------|-->|------------|             |------------|             |----------|
  | Current Frame | +-| function 2 |<- next -----| function 1 |<- next -----| C Host   |
  +---------------+ | +------------+             +------------+             +----------+
                    |         +------+
                    +- next ->| NULL |
                              +------+

  === Call Frame ===

  +-----------------+------------+------------+-----+------------+
  | Function Object | Argument 1 | Argument 2 |     | Argument N |
  |-----------------|------------|------------| ... |------------|
  | ci->func.p      | func + 1   | func + 2   |     | func + N   |
  +-----------------+------------+------------+-----+------------+
  +------------------+-----+------------------+--------------------------+----------+-----+
  | Local Variable 1 |     | Local Variable N |                          | Top      |     |
  |------------------| ... |------------------| ... Temporary Values ... |----------| ... |
  |                  |     |                  |                          | L->top.p |     |
  +------------------+-----+------------------+--------------------------+----------+-----+
                                                                         ^-- Free Space --^

  === Register-Based Layout ===

  Lua's VM uses a register-based model, where each function has a set
  of virtual registers — in reality, stack positions.

  +----------------+--------------------------+------------+-------------+----------+
  | Base           | Register 0               | Register 1 | Register N  | Unused   |
  |----------------|--------------------------|------------|-------------|----------|
  | ci->func.p + 1 | Fixed Arguments / Locals | Locals     | Temporaries | L->top.p |
  +----------------+--------------------------+------------+-------------+----------+
#+end_example

  struct lua_State {
      // CommonHeader ------------+
      struct GCObject* next;  //  |
      lu_byte tt;             //  |
      lu_byte marked;         // <+
      // Type for thread status/error codes.
      TStatus status;
      // First free slot in the stack.
      StkIdRel top;
      // Reference to state shared by all threads. Contains mostly data
      // for memory allocation and garbage collection.
      struct global_State* l_G;
      // Call information for current function.
      CallInfo* ci;
      // End of stack (last element + 1)
      StkIdRel stack_last;
      // Stack base.
      StkIdRel stack;
      // List of open upvalues in this stack.
      UpVal* openupval;
      // List of to-be-closed variables.
      StkIdRel tbclist;
      // List of garbage-collectable objects.
      GCObject* gclist;
      // List of threads with open upvalues.
      struct lua_State* twups;
      // Current errory recovery point.
      struct lua_longjmp* errorJmp;
      // Call information for first level (C host).
      CallInfo base_ci;
      // Function to be called by the debugger.
      volatile lua_Hook hook;
      // Current error handling function (stack index).
      ptrdiff_t errfunc;
      // Number of nested, (non-yieldable | C) calls.
      l_uint32 nCcalls;
      // Last program counter traced.
      int oldpc;
      // Number of items in call information list.
      int nci;
      int basehookcount;
      int hookcount;
      volatile l_signalT hookmask;
      // Information about transferred values for (call | return) hooks.
      struct {
          // Offset of first value transferred.
          int ftransfer;
          // Number of values transferred.
          int ntransfer;
      } transferinfo;
  };

  // === Function Call Information / Call Frame ===

  struct CallInfo {
      // Function index in the stack.
      StkIdRel func;
      // Top index for this function.
      StkIdRel top;
      // Dynamic call link.
      struct CallInfo *previous, *next;
      union {
          // === Lua Function ===
          struct {
              // Saved pointer to bytecode instruction.
              const Instruction* savedpc;
              // Function tracing lines/counts.
              volatile l_signalT trap;
              // Number of extra arguments in variable-argument functions.
              int nextraargs;
          } l;
          // === C Function ===
          struct {
              // Continuation in case of yields.
              lua_KFunction k;
              ptrdiff_t old_errfunc;
              // Context information in case of yields.
              lua_KContext ctx;
          } c;
      } u;
      union {
          // Called function index. Used only by C functions during
          // a protected call.
          int funcidx;
          // Number of values yielded. Used only by functions
          // that are yielding.
          int nyield;
          // Number of values returned.
          int nres;
      } u2;
      // Bit mask denoting function status.
      // - number of results.
      // - metamethod?
      // - etc.
      l_uint32 callstatus;
  };

  // === Lua Stack ===

  // Lua stack entries. Field "tbclist" forms a list of all
  // to-be-closed variables active in this stack. Dummy entries are
  // used when the distance between two tbc variables does not fit
  // in an unsigned short. They are represented by delta == 0.
  // Their real delta is always the maximum value that fits in
  // that field.
  typedef union StackValue {
      TValue val;
      struct {
          // Lua value.
          Value value_;
          // Type tag.
          lu_byte tt_;
          unsigned short delta;
      } tbclist;
  } StackValue;

  // Index to stack elements.
  typedef StackValue* StkId;

  // === Stack Pointers ===
  typedef union {
      // Pointer
      StkId p;
      // Offset used during stack reallocation.
      ptrdiff_t offset;
  } StkIdRel;

*** Functions, Closures, and UpValues

#+begin_quote
  "When Lua compiles a function it generates a prototype containing the virtual machine
   instructions for the function, its constant values (numbers, literal strings, etc.),
   and some debug information. At run time, whenever Lua executes a function...end expression,
   it creates a new closure. Each closure has a reference to its corresponding prototype,
   a reference to its environment (a table wherein it looks for global variables), and an
   array of references to upvalues, which are used to access outer local variables...

   Lua uses a structure called an upvalue to implement closures. Any outer local variable
   is accessed indirectly through an upvalue. The upvalue originally points to the stack
   slot wherein the variable lives. When the variable goes out of scope, it migrates into
   a slot inside the upvalue itself...

   Unlike its inner functions, the function that declares the variable accesses [that variable]
   as it accesses its own local variables: directly in the stack."

  — The Implementation of Lua 5.0
#+end_quote

** Parsing and Compilation

The Lua compiler uses a single-pass, recursive descent, operator precedence climbing parser
with interleaving syntax analysis and code generation. The compiler outputs ~Proto~ —
the static compilation of a Lua function, containing metadata and executable bytecode.

1. Lua Source Code: ~.lua~ files

2. Buffered IO: ~lzio.c~

3. Lexer: ~llex.c~

4. Parser: ~lparser.c~

5. Code Generation: ~lcode.c~

6. Function Prototype: bytecode + metadata

7. Virtual Machine: wraps function prototypes in closures, executes bytecode

#+begin_src c
  LClosure* luaY_parser(lua_State* L, ZIO* z, Table* anchor, Mbuffer* buff,
                        Dyndata* dyd, const char* name, int firstchar) {
      LexState lexstate;
      FuncState funcstate;
      LClosure* cl;
      /* Scanner Table */
      lexstate.h = anchor;
      /* Create main closure. */
      cl = luaF_newLclosure(L, 1);
      /* Anchor closure in scanner table. */
      luaD_anchorobj(L, anchor, obj2gco(cl));
      funcstate.f = cl->p = luaF_newproto(L);
      luaC_objbarrier(L, cl, cl->p);
      /* Create and anchor TString. */
      funcstate.f->source = luaS_new(L, name);
      luaC_objbarrier(L, funcstate.f, funcstate.f->source);
      lexstate.buff = buff;
      lexstate.dyd = dyd;
      dyd->actvar.n = dyd->gt.n = dyd->label.n = 0;
      luaX_setinput(L, &lexstate, z, funcstate.f->source, firstchar);
      /* Parse source code. */
      mainfunc(&lexstate, &funcstate);
      lua_assert(!funcstate.prev && funcstate.nups == 1 && !lexstate.fs);
      lua_assert(dyd->actvar.n == 0 && dyd->gt.n == 0 && dyd->label.n == 0);
      return cl;
  }

- *IO*: ~struct ZIO~ buffers input to lexer.

- *Lexer State*: ~struct LexState~ maintains lexical analysis state across the entire compilation,
  including IO, current token, and lookahead information.

- *Dynamic Data*: ~struct Dyndata~ tracks dynamic data structures used by the parser. These include
  active local variables and pending gotos and labels.

- *Function State*: ~struct FuncState~ represents the current function being compiled, tracking
  register allocation, constants, and upvalues. A series of these nodes creates a stack
  tracking lexical scope for nested function definitions.

- *Block Control*: ~struct BlockCnt~ tracks state for a syntactic block (function body, loops, if statement).
   A series of these nodes creates a stack, tracking variable visibility and pending jumps. Generates
   close instructions for pending upvalues.

*** Expression Parsing and Operator Precedence

#+begin_src c
  /* Priority table for binary operators. */
  static const struct {
      lu_byte left;
      lu_byte right;
  } priority[] = {
      {10, 10}, {10, 10},         /* '+' '-' */
      {11, 11}, {11, 11},         /* '*' '%' */
      {14, 13},                   /* '^' (right associative) */
      {11, 11}, {11, 11},         /* '/' '//' */
      {6, 6},   {4, 4},   {5, 5}, /* '&' '|' '~' */
      {7, 7},   {7, 7},           /* '<<' '>>' */
      {9, 8},                     /* '..' (right associative) */
      {3, 3},   {3, 3},   {3, 3}, /* ==, <, <= */
      {3, 3},   {3, 3},   {3, 3}, /* ~=, >, >= */
      {2, 2},   {1, 1}            /* and, or */
  };

  /* Priority for unary operators */
  #define UNARY_PRIORITY 12

  /*
    sub-expression -> (simple expression | unary operation) { binary operation }
    where binary operation is any binary operator with a priority higher than limit.
  */
  static BinOpr subexpr(LexState* ls, expdesc* v, int limit) {
      BinOpr op;
      UnOpr uop;
      enterlevel(ls);
      uop = getunopr(ls->t.token);
      /* prefix (unary) operator? */
      if (uop != OPR_NOUNOPR) {
          int line = ls->linenumber;
          /* Skip operator. */
          luaX_next(ls);
          subexpr(ls, v, UNARY_PRIORITY);
          luaK_prefix(ls->fs, uop, v, line);
      } else {
          simpleexp(ls, v);
      }
      /* Expand while operators have priorities higher than limit. */
      op = getbinopr(ls->t.token);
      while (op != OPR_NOBINOPR && priority[op].left > limit) {
          expdesc v2;
          BinOpr nextop;
          int line = ls->linenumber;
          /* Skip operator. */
          luaX_next(ls);
          luaK_infix(ls->fs, op, v);
          /* Read sub-expression with higher priority. */
          nextop = subexpr(ls, &v2, priority[op].right);
          luaK_posfix(ls->fs, op, v, &v2, line);
          op = nextop;
      }
      leavelevel(ls);
      /* Return first untreated operator. */
      return op;
  }

  static void expr(LexState* ls, expdesc* v) { subexpr(ls, v, 0); }

*** Coroutines

Coroutines, or threads, are represented by ~lua_State~ structures, where each coroutine
maintains its own stack and call chain. Shares global state with the main thread
and other coroutines.

| state           | description                            |
|-----------------+----------------------------------------|
| ~LUA_OK~        | Ready to run or has finished executing |
| ~LUA_YIELD~     | Suspended via ~lua_yieldk~             |
| ~LUA_ERRRUN~    | Runtime error occurred                 |
| ~LUA_ERRSYNTAX~ | Syntax error during parsing            |
| ~LUA_ERRMEM~    | Memory allocation error                |
| ~LUA_ERRERR~    | Error while running error handler      |

*** Exception Handling

Exception handling is a chain of ~lua_longjmp~ structures that form a stack of recovery points.
Each protected call inserts a new node in the chain. The function ~luaD_throw~ propagates errors.

Exception handling is specific to the given platform:

- *C++*: ~throw~, ~try~, and ~catch~

- *POSIX*: ~_longjmp~ and ~_setjmp~ — more efficient than ~_longjmp~ and ~setjmp~

- *ISO C*: ~longjmp~ and ~setjmp~
